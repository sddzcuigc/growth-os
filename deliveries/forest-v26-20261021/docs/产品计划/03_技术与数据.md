# 技术与数据

第一项仍然是各终端共用数据。沿用原项目可维护的前端、账号和数据库，核实后修复，不为改定位重写整套系统。

## 数据对象

| 对象 | 关系与要求 |
|---|---|
| 分类 | 用于生活、学习等整理，可调整；项目可以跨分类 |
| 技能 | 稳定 ID；名称、完成标准、练习方法、分类和历史 |
| 大技能拆解 | 引用已有技能，不复制独立历史；允许按孩子情况继续拆解 |
| 项目 | 具体目标与结果，引用多项技能，保存应用记录和复盘 |
| 练习与复习 | 同一技能的真实尝试，记录时间、帮助、结果和来源 |
| 项目应用 | 哪次项目用了哪些技能、如何用、观察到什么 |
| 成就与作品 | 关联实际练习或项目结果，区分本人完成、帮助和代做 |

分类、小技能、大技能和项目在数据上分别表达。新建一次午餐项目不应复制“买菜”的技能和复习历史。大小技能引用要避免循环；删除已有技能时提示受影响项目，优先归档并保留历史。

## 多端同步验收

手机、平板、电脑使用统一入口和同一账号，或用共同家庭邀请共享数据。切换当前孩子是本机视图，不应把另一台设备正在看的孩子强行切走。

一端新增或修改技能，其他端自动读到；离线练习先保存到账号对应的本机队列，联网后重试同一个事件 ID；重复提交不重复记账；服务重启后数据仍在。

两台设备分别修改不同内容时可安全合并；修改同一事实时保留两份并提示处理。旧数据有备份，账号切换后不把前一个家庭的记录上传给后一个家庭。

同步应保留新增分类、拆解与项目字段；“能够存储和同步这些字段”与“已经实现其完整编辑界面”分开验收。

## 规则与 AI

练习次数、时长、帮助程度、真实项目应用分别记录。AI 可辅助提出拆解或练习建议，孩子及家长可调整；它不能凭一次点击或照片替代实际检验。

确定性程序负责权限、重复处理、奖励、状态与统计。全栈测试同时核对用户操作、数据库和最终显示，不以页面能打开证明同步完成。

## 交付

保留原版本；重要迭代生成独立交付目录，包含源码、可运行内容、配置说明、升级备份、真实案例、截图与验收结论。

终端矩阵明确区分浏览器适配、可安装网页应用、原生工程、已经构建的安装包和真实设备验收。iOS 等平台需要相应构建和签名环境；没有安装包和设备证据时不能宣称原生客户端全部完成。
